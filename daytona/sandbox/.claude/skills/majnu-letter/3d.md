# 3D with Three.js

Part of the `majnu-letter` skill. Every page rule in `SKILL.md` still applies; this file adds the one exception to rules 1 and 2 and tells you how to use it well.

## When to use 3D

Use a Three.js scene when the request asks for depth, an object or a place you can look into: "a snow globe with our city inside", "a spinning record", "a box that opens", "floating lanterns", "a little planet", "a paper boat on water", "make it 3D". The scene is the decoration; the letter is still the page.

Do not use 3D when the request is about paper, print, type or flat illustration (a postcard, a poster, a ticket, a newspaper, a watercolour), when it asks for something calm and simple, or when CSS and SVG already give the effect (a card flip, parallax, a glow, falling petals). When in doubt, do not: a good flat page beats a slow 3D one. Never make the letter's words part of the 3D scene.

## How to load it

One copy of three.js (version 0.187.0) is hosted on our site. It is the only script a page may load. Import it once, in one `<script type="module">`, with exactly this path:

```html
<script type="module">
  import * as THREE from "/vendor/three/0.187.0/three.module.min.js";
  // your scene
</script>
```

The checker accepts exactly this, character for character: one import of that path (or of `"three"` with the single import map `{"imports":{"three":"/vendor/three/0.187.0/three.module.min.js"}}`). Anything else is refused and the page is thrown away: a second import, another version or file, `three/addons/...`, `https://...`, a query string, `import()`, `export ... from`.

What that means for the code:

- **Core three.js only.** No addons: no `OrbitControls`, `GLTFLoader`, `RoundedBoxGeometry`, `TextGeometry`, `EffectComposer`. Write the little you need yourself (a drag-to-rotate is twenty lines of pointer events).
- **No loaders and no files.** No `TextureLoader`, `FileLoader` or any other `...Loader`: the page has no network. Build shapes from the core geometries (`BoxGeometry`, `SphereGeometry`, `CylinderGeometry`, `ConeGeometry`, `TorusGeometry`, `CapsuleGeometry`, `IcosahedronGeometry`, `LatheGeometry` for turned shapes such as a globe base or a vase, `ExtrudeGeometry` from a `Shape` for flat silhouettes such as a skyline or a heart, `TubeGeometry`), `Points` for snow, stars or confetti, and `InstancedMesh` for many copies of one thing. A texture, if you need one, is a `CanvasTexture` from a canvas you draw in the script.
- **Version notes (0.187).** `THREE.Clock` is deprecated and logs a warning: use `const timer = new THREE.Timer()` and call `timer.update(time)` in the loop, then `timer.getDelta()` / `timer.getElapsed()`. Animate with `renderer.setAnimationLoop(fn)`. Colours are sRGB by default; leave `outputColorSpace` alone.

## The still fallback (required)

The page must be complete and beautiful before and without the scene. Build it in this order:

1. **The HTML page first.** All the words in the markup, as `SKILL.md` requires, and a still picture of the scene drawn in inline SVG or CSS (the snow globe as an SVG, say) in the place the canvas will go. This is what shows when WebGL is missing, when the script fails, when the GPU drops the context, and with reduced motion if you choose.
2. **The scene replaces the still picture only once it works.** Create the renderer inside `try`; if that throws, or the browser has no WebGL, do nothing: the still picture stays. Hide the still picture only after the first frame has rendered.
3. **Reduced motion.** If `matchMedia("(prefers-reduced-motion: reduce)").matches`, nothing moves: render one still frame and stop (or keep the SVG). No animation loop, no camera drift, no particles falling. Listen for changes to the setting and stop the loop if it turns on.
4. **Context lost.** On `webglcontextlost`, stop the loop and show the still picture again.

```js
const still = document.getElementById("scene-still");   // the SVG picture
const holder = document.getElementById("scene");         // where the canvas goes
const reduce = matchMedia("(prefers-reduced-motion: reduce)");
let renderer;
try {
  renderer = new THREE.WebGLRenderer({ antialias: true, alpha: true, powerPreference: "low-power" });
} catch {
  renderer = null; // no WebGL: the still picture stays
}
if (renderer) {
  renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
  renderer.domElement.setAttribute("aria-hidden", "true");
  holder.appendChild(renderer.domElement);
  // ... build the scene, size it from holder with a ResizeObserver ...
  renderer.render(scene, camera);
  still.hidden = true;
  renderer.domElement.addEventListener("webglcontextlost", () => { renderer.setAnimationLoop(null); still.hidden = false; });
  // start the loop only when !reduce.matches (see the budget below)
}
```

## The budget (a phone is the target)

- **One scene, one renderer, one canvas** on the page.
- **Under 50,000 triangles in total.** Keep segment counts modest (a sphere of 48 × 32 is plenty) and use `InstancedMesh` or `Points` for anything repeated. Snow or stars: at most a few thousand points.
- **No textures from outside**, ever. Canvas textures you draw: at most 1024 × 1024, and few of them.
- **Cheap materials and light.** `MeshStandardMaterial`, `MeshLambertMaterial` or `MeshBasicMaterial`; at most three lights; shadows off (fake a contact shadow with a dark transparent disc). No `MeshPhysicalMaterial` transmission or refraction: it re-renders the scene. Glass is a transparent standard material (`transparent: true, opacity: 0.15–0.3, roughness: 0.05`) with a bright rim from the lights.
- **60 fps on a mid-range phone.** Pixel ratio capped at 2, no allocations inside the loop (reuse vectors), no post-processing.
- **Pause when nobody is looking.** Stop the loop when the page is hidden (`document.visibilitychange`) and when the canvas scrolls out of view (`IntersectionObserver`); start it again when it comes back. `renderer.setAnimationLoop(null)` stops it.
- **Size the canvas from its box**, not the window, with a `ResizeObserver`; update `camera.aspect` and call `camera.updateProjectionMatrix()`.

## Accessibility

- **The words stay real HTML,** over or beside the canvas, never drawn into it. A screen reader and a search for text must find every word of the letter.
- The canvas is decoration: `aria-hidden="true"`, and give the scene's holder `role="img"` with an `aria-label` describing it ("A snow globe with a small city inside") or mark it `aria-hidden="true"` if the still picture already carries the description.
- **Readable over the scene.** Text over a moving 3D background needs a solid or frosted panel behind it, keeping 4.5:1 contrast at every moment of the animation.
- **Scrolling still works.** The canvas must not trap touch: leave `touch-action` alone unless the scene has a drag, and then use `touch-action: pan-y` so a vertical swipe still scrolls the page. Interaction is optional and never needed to read the letter; anything you can do with a drag you can also do with a `<button>` ("Shake the globe").
- Keyboard focus never lands on the canvas.
